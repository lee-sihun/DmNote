# 로컬 워크플로 규칙

협업 상대는 외부 CLI(Codex)가 아니라 **자체 서브에이전트**(Agent 도구, `general-purpose` + `model: opus`)입니다.
계획 검증·코드 리뷰·디버깅 조사는 서브에이전트가 수행하고, **코드 수정은 항상 메인 에이전트가 직접** 합니다.

## 구현 요청 시 필수 행동

사용자가 다음 중 하나에 해당하는 요청을 하면, **무조건 첫 번째 도구 호출로 `Skill` 도구를 사용하여 `/agent-plan`을 실행**해야 합니다:
- 기능 구현/추가 ("~해줘", "~추가해줘", "~구현해줘", "~만들어줘")
- 리팩토링/아키텍처 변경
- 설계 논의/계획 수립

이것은 이 프로젝트의 **절대 규칙**입니다:
1. 사용자 메시지를 읽는다
2. 구현 요청인지 판단한다
3. 구현 요청이면 → **즉시 `Skill(skill: "agent-plan", args: "사용자 요청 내용")`을 호출한다**
4. Read, Grep, Glob, Agent 등 다른 도구는 `/agent-plan` 스킬 실행 후에만 사용한다

**위반 금지**: 파일을 먼저 읽거나, 코드를 분석하거나, 계획을 직접 세우는 행위는 이 규칙의 위반입니다.

예외 (plan 생략 가능):
- 단순 버그 수정(1~2줄), 오타/포맷팅 수정, 질문/설명 요청
- 변경 파일 1~2개 이내 + 기존 패턴 재사용인 단순 기능 추가 (API 한두 개 연결, 옵션 추가 등)

## 기본 워크플로

모든 구현 작업은 다음 워크플로를 따릅니다.

### 1. 계획 수립 (필수)
위 규칙에 따라 `/agent-plan` 스킬을 호출합니다.
- 메인 선분석 → 서브에이전트 독립 검증 → 최종 계획 확정

### 2. 단계별 구현 + 코드 리뷰
확정된 계획을 단계별로 나누어 구현합니다.
- 한 번에 모든 변경을 하지 않고, 논리적 단위로 분리
- 중간 단계의 `/agent-review`는 재량껏 결정 (복잡하거나 리스크가 높은 단계는 받기 권장)
- **최종 커밋(작업 완료 커밋) 전에는 반드시 `/agent-review`를 실행한다** (절대 규칙)
- 리뷰 없이 최종 커밋하는 것은 이 규칙의 위반이다

**위반 금지**: 최종 커밋 전 `/agent-review` 없이 작업을 완료하는 행위는 이 규칙의 위반입니다.

### 2-1. TDD (복잡한 로직)
복잡한 비즈니스 로직, 알고리즘, 상태 관리 코드를 구현할 때는 TDD 방법론을 적용합니다.
- **Red**: 구현 전에 실패하는 테스트를 먼저 작성
- **Green**: 테스트가 통과하는 최소한의 구현 작성
- **Refactor**: 테스트를 유지하면서 코드 정리
- 판단 기준: 순수 함수/계산 로직, 스토어 상태 변환, 복잡한 조건 분기, 파싱/직렬화 코드

### 3. 빌드/린트 검증
변경 내용에 따라 적절한 검증을 수행합니다.
- Rust 변경: `cargo check`, `cargo clippy`
- TypeScript 변경: `npx tsc --noEmit`, `npm run lint`
- **리뷰 요청 전에 검증을 먼저 통과**시키고, 리뷰어에게는 도구가 못 잡는 로직/동작에 집중하도록 합니다.

### 4. 자동 커밋
각 단계의 검증이 통과되면 해당 변경사항을 즉시 커밋합니다.
- 커밋 메시지는 변경 내용에 맞게 작성
- 단계별로 커밋하여 git 히스토리를 깔끔하게 유지

### 워크플로 예시
```
사용자: "키보드 입력 시스템에 딜레이 옵션 추가해줘"

1. Skill(skill: "agent-plan", args: "키보드 입력 시스템에 딜레이 옵션 추가") ← 무조건 첫 번째
2. 단계 1: Rust 백엔드 커맨드 추가 → 커밋 (중간 단계, 재량 리뷰)
3. 단계 2: 프론트엔드 설정 UI 추가 → 커밋 (중간 단계, 재량 리뷰)
4. 단계 3: 오버레이 반영 로직 수정 → /agent-review (필수, 최종 커밋 전) → 커밋
```

### 5. 최종 보고
모든 단계가 완료되면 작업 결과를 정리하여 보고합니다.
- 변경된 파일 목록과 각 변경 요지
- 커밋 히스토리 요약
- 서브에이전트 리뷰에서 나온 주요 피드백과 반영 여부
- 남은 리스크나 후속 작업이 있으면 명시

## 디버깅

버그 원인 추적이 필요하면 `/agent-debug`를 사용합니다.
- 메인 선분석 → 서브에이전트 독립 조사(READ-ONLY) → 원인 확정 → 메인이 직접 수정

## 예외
- 사소한 변경(오타, 포맷팅, import 정리, 번역 텍스트 등)은 plan/review 없이 직접 처리
- 긴급 핫픽스는 plan 없이 구현 후 review만 수행
- **review 생략은 사소한 변경에만 허용. 기능 구현/수정의 최종 커밋은 반드시 review 후 커밋**
